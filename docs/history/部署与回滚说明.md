## 已具备的两个云端值

1. ECS 实例角色已经挂载，并能从 ECS 元数据接口返回临时凭证。
2. 一个允许浏览器对单个 `transfer/v1/.../payload` Object 进行 Multipart 上传的 RAM Role ARN：
   `acs:ram::<account-id>:role/<transfer-upload-role>`。

实际 ARN：`acs:ram::<account-id>:role/changyi-transfer-upload-role`。

不使用长期 AccessKey 写入应用；没有这两个值时，服务应保持未启用状态。

## RAM 最小权限建议

建议建立两个角色：

- ECS 实例角色：信任 ECS，允许 `sts:AssumeRole` 到浏览器上传角色；允许应用对 `transfer/v1/*` 执行 `oss:GetObject`、`oss:DeleteObject`。
- 浏览器上传角色：只允许 `oss:PutObject`、`oss:AbortMultipartUpload`、`oss:ListParts`，资源限定为 `acs:oss:*:*:your-oss-bucket/transfer/v1/*`。

浏览器拿到的是后端按单 Object 进一步收窄的 15 分钟 STS，不拿长期密钥，也不能列 Bucket。

### 可直接粘贴的 RAM 配置

上传角色的信任策略，把 `<account-id>` 和 ECS 角色名替换为实际值：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "sts:AssumeRole",
      "Principal": {
        "RAM": ["acs:ram::<account-id>:role/changyi-transfer-ecs-role"]
      }
    }
  ]
}
```

上传角色权限策略：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject", "oss:AbortMultipartUpload", "oss:ListParts"],
      "Resource": ["acs:oss:*:*:your-oss-bucket/transfer/v1/*"]
    }
  ]
}
```

ECS 角色还需要对同一前缀拥有 `oss:GetObject`、`oss:DeleteObject`，并允许
`sts:AssumeRole` 到上传角色。把 ECS 角色挂载到实例时，当前 RAM 管理员需要具备
`ram:PassRole`。创建完成后，把上传角色 ARN 发回即可。

## 访问方式

用户于 2026-10-09 明确要求所有人可访问、不设登录口令。当前主页、上传、取件和最近文件列表均公开，不要求团队口令。OSS Bucket 仍保持私有，文件下载使用限时签名 URL；浏览器上传使用限制到单个 Object 的临时凭证。

## 可回滚部署顺序

1. 只读确认 8810 仍为空闲、现有服务和 `nginx -t` 正常。
2. 写入独立 env 和 `changyi-transfer.service`，执行 `systemctl daemon-reload`，不触碰现有单元。
3. 启动新单元并只检查 `127.0.0.1:8810/transfer/api/health`。
4. 备份 `/etc/nginx/sites-available/argon-kb`，仅加入 `/transfer/` 两个 location；`nginx -t` 成功后才 `systemctl reload nginx`。
5. 通过 HTTPS 登录、上传小测试文件、下载、过期和删除验收。

回滚只停用新单元、恢复 Nginx 备份并优雅 reload；不重启 ArgonType、FrameSeen 或其他现有服务。

## 失败闸门

- RAM 元数据仍返回 404：不启动正式服务，不开放 Nginx 路由。
- Bucket 只读检查发现已有非 `transfer/v1/` 对象：停止复用，改建专用 Bucket，不迁移、不删除原对象。
- Nginx 配置测试出现新增 warning 以外的 error：不 reload，恢复备份。
- 现有服务 smoke test 与部署前不一致：立即停止新单元，恢复 Nginx，保留新发布目录供审计。
